## Threat model

This repository is the steering layer Claude Code loads. A change on `master` is a behavior change for the next session that pulls it.

- Spoofing. `commands/improve.md` shows a command that reads a driver key into an `Authorization` header. A session that runs it handles a credential the hook was built to keep out of the transcript.
- Tampering. The self-approval classifier accepts a push of `HEAD` and of `refs/heads/master`. `line-scope.mjs` marks live gate lines in `/improve` as calibration a model-refresh may edit. `master` has no branch protection, so CI is not required for a push.
- Repudiation. This repo does not write an audit log. The Worker does. That split is stated in the command.
- Information disclosure. The same classifier accepts `gh pr create --body-file` of a key path. A relative `Get-Content .capsid\*.key` is not treated as a key read.
- Denial of service. The disk preflight and the heavy-work lock are the controls for a full disk and for overlapping installs. Both fail closed in the paths the tests cover.
- Elevation of privilege. Step 4b is the only self-approval. A default-branch push, a force push, a deploy, and a merge are supposed to stay with the human. The classifier's default-branch check is the word `master` or `main` only.

## 1. Security

### CS-1 MAJOR. The self-approval classifier accepts a default-branch push and any `gh pr create`

Area: security. Confidence: high. File: `scripts/block-command.mjs`, lines 13, 44 to 46, and 49 to 51.

`DEFAULT_BRANCHES` is the set `master` and `main`. The push is self-approvable when the positional branch is any other single word. Measured with the function:

- `git push -u origin HEAD` is self-approvable.
- `git push -u origin refs/heads/master` is self-approvable.
- `git push -u origin refs/heads/main` is self-approvable.
- `git -C C:\work\wt push -u origin HEAD` and the same command with `refs/heads/master` are self-approvable.
- `git push -u origin feature; gh pr create --body-file C:\Users\email\.capsid\agent-seat.key` is self-approvable, classes `push_branch` and `open_pr`.
- `git push -u origin feature; gh pr create --repo evil/evil` is self-approvable.

`git push -u origin HEAD` updates the remote branch of the same name as the current branch. On `master`, that is a push of `master`. `git push origin refs/heads/master` updates `refs/heads/master` on the remote. `gh pr create` is accepted with any arguments after the verb, so `--body-file` can put a key file into a pull request body.

The tests lock the word `master`, a `cd` segment, a force flag, and a bare `gh pr create` with no push. Those stay red when the set is emptied (plant below). The equivalents above stay green.

The file header says the Worker classifier is the authority and that this function is the shape the command tells a driver to block with. A command this function should refuse is a push nobody confirmed. The Worker was not re-read in this audit. A driver that mirrors this function, and a Worker that was written to match it, both approve the commands above.

Smallest fix: treat `HEAD`, and any branch whose last segment is `master` or `main`, as a default-branch push. Accept `gh pr create` only with `--repo`, `--base`, `--head`, `--title`, and `--body`, and refuse `--body-file`.

- `type .capsid\operator.key` is not a secret read.
- `Get-Content '.capsid\agent-seat.key'` is not a secret read.
